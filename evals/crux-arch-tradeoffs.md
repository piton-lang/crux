# crux-arch-tradeoffs: evaluation scenarios

Run in a fresh agent session with the built skill installed (alone, without the other architecture skills, to prove independence), against a scratch Piton project prepared as stated. Record specification hashes before the run where modification is in question.

## Scenario

Seed requirements that demand exact geometry and robustness over performance, then invoke: 'Compare B-Rep and implicit (F-Rep) representations for our kernel.' Expect the decision, alternatives, hard constraints separated from evaluation criteria, criteria selected for this project without asking the user to re-rank what specs prioritize, evidence labelled (verified, benchmark, estimate, inference, unknown), incompatible benchmarks never compared directly, hard-constraint violators eliminated, sensitivity analysis showing what would flip the result, and a reasoned recommendation or a concrete experiment when evidence is inconclusive. No decision recorded without user selection and authorization.

## Independence and collaboration checks

- The skill works when the other four architecture skills are not installed.
- When a subtask genuinely belongs to another installed skill, it is discovered and delegated to with a narrow objective, or recommended, without a recursive loop and without surrendering the primary result.
- Proposals, alternatives, assumptions, and research findings are never presented as confirmed requirements or decisions; nothing is modified without authorization.

## Live verification result

Passed live, installed alone. On comparing B-Rep, implicit F-Rep, and a hybrid, the agent separated hard constraints (exact geometry, robustness, offline) from evaluation criteria without asking the user to re-rank established priorities, labelled evidence kinds, performed sensitivity analysis, and gave a reasoned recommendation with remaining uncertainty, recording no decision and changing no file (hash verified).
